# Administration interface

The shared `/workspace` landing now uses the Living Heritage shell and session role navigation. `/administration/clinical-assignments` uses the same shell and shared form/status styles; `/administration` retains its feature-specific staff table and dialog. The old top navbar and session strip are removed. Sign-out remains available in each protected page header. See [shared workspace implementation](../../../../docs/ui/shared-workspace-implementation.md).

AUTH-06's [real full-stack verification suite](../../../tests/fullstack/README.md) additionally runs Chromium against the actual Go API and PostgreSQL over isolated HTTPS using `npm run test:fullstack`. Its CI job is separate from the simulated API regression suite below. F review, trusted deployment and final DEC07/module policy acceptance remain separate gates.

`session.tsx` owns memory-only session state, startup/focus restoration, expiry handling and logout. `sign-in-form.tsx` uses the existing cookie API. `/workspace` shows role work areas; the shared layout guard is UI behavior, never a substitute for Go role/record checks. `apiMutation` obtains current CSRF and never automatically retries writes. `/administration` implements staff listing/creation, role selection and disabling through the protected AUTH-04 API. See [login setup](../../../../docs/api/auth-04-login.md), [the staff contract](../../../../docs/api/auth-04-staff.md) and [the administration guide](../../../../docs/guides/member-a-administration.md) for setup, verification and staff instructions. No public signup, remember-me policy or password recovery is introduced.

AUTH-06/QA-04 integration repair reconnects the heritage sign-in page to this single form and removes the route-local demo forms. Failed session lookup never creates a session, including on localhost. Reception and dashboard require authentication; reception additionally requires the receptionist role. The shared session hook exposes `signOut`/`signingOut` so protected page headers use fresh-CSRF logout and honest failure handling. `/dashboard` redirects to the role-based workspace. Public access help collects no credentials or account requests. Reception remains a labelled synthetic preview; actual registration uses `/patients`.

Run `npm run build`, `npx playwright install chromium`, then `npm run test:browser` from `frontend/`. The suite uses Chromium and synthetic intercepted API responses against the production build on port 3100. CI installs Chromium/dependencies and runs it after the frontend build. These browser regressions supplement the real Go/PostgreSQL tests; they do not prove HTTPS cookies, actual backend revocation or full AT01/F acceptance.

The same branch now implements the supplied Figma sign-in (`5:23`), staff table (`7:499`), create-account dialog (`9:656`), expired-session (`9:612`) and access-denied (`9:618`) designs. `heritage.module.css` scopes DM Sans/Lora, paper textures and exported SVGs to these screens. Staff values and roles come from the API; no mock staff identities are rendered as real accounts. The API lacks staff display names, so the first column identifies account/current-user scope and Login shows the actual identifier. Reference-data/audit navigation remains disabled, while existing pagination, clinician assignment navigation, session revocation and server permission boundaries remain available. Native dialogs trap focus, support Escape and restore the opener. The browser suite now includes account actions and 1366×768/1024×768 checks; asset provenance is in [public/brand](../../../public/brand/README.md).
