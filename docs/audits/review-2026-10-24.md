## Follow-ups, not speculative changes

| Item | Evidence / next step |
| --- | --- |
| Patient search query volume | Static count for 25 visible reception records: 2 CanSearch queries + 1 candidate query + 25 × (3 CanRead + 2 readPatient) = 128 statements, before authentication/transaction overhead. The snapshot repair removes one query per record. Measure a real PostgreSQL workload before batching retrieval/permissions; do not cache authorization across transactions. No latency/throughput improvement is claimed. |
| Substring search | `strpos(lower(...))` does not benefit from the existing name/ID index as an indexed substring lookup. Profile the intended synthetic workload before adding indexing/dependencies. AT14 remains open. |
| Auth identifier ledger | Arbitrary failed identifiers can grow the throttle ledger. DEC07 still needs source-level abuse and retention/cleanup review before deployment; no invented retention default is introduced. |
| Audit reader revocation | Authorization currently precedes retrieval without one shared transaction. No audit route is exposed; define record/revocation semantics with its future adapter before opening it. |
| Billing handoff | Empty invoice/report slices can serialize as null; one-use custom integer formatting can use strconv. Issuing commits before response re-fetch, so a later read failure can report failure after a committed issue. Aggregate totals beyond int64 fail safely but need validation/error classification. These routes remain closed; E/D should review their API semantics before exposure. |
| Style | Several existing long signatures/calls and dense conditions warrant touched-line cleanup. A repository-wide cosmetic rewrite would add merge conflicts without repairing a defect. |
| Token input bound | `secretHash` decodes before rejecting non-32-byte data. An exact encoded-length check is a small future input-bound improvement; it is not a measured performance bottleneck. |
