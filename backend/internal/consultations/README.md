# Consultation drafts (TASK-CON-01)

Member B owns this slice; Member C reviews it. SRS CON-01 and AT03 require a consultation draft to exist without a care plan. Migration `000006_consultation_drafts.up.sql` creates draft-only rows linked to patients and staff, with a version for concurrent edits. `Create`, `Get`, and `Update` preserve Unicode note text, reject blank/oversized drafts, lock and version edits, and insert create/update audit metadata in the same transaction. Audit events contain no note body.

Every service call requires a transaction-scoped `AccessPolicy`. A nil policy denies access. The running API now registers protected clinical routes when authentication is explicitly configured. `AssignedPolicy` checks the active clinician role and current patient assignment in each transaction; revocation serializes with protected reads and writes. An administrator can grant/revoke assignments without gaining note access. The signed clinic source and integrated AT03 journey still need evidence before acceptance.

TASK-CON-02 adds migration `000007_consultation_signing.up.sql`. A versioned `Sign` moves the draft into a separate `signed_text` column and stores server-derived signer and time. Signed consultations cannot be updated or deleted, including through direct SQL; addenda are separate insert-only rows ordered by recorded time and ID. `AddCorrection` requires a nonblank reason and body, and writes audit metadata in the same transaction. `Get` returns the signed original and dated addenda only after the same transaction-scoped record-access check. `AssignedPolicy` gates signing and corrections for the active clinician assigned to the patient. No text or correction reason enters audit events.

The previous draft-only migration remains untouched. The reason limit is 2,048 UTF-8 bytes and the body limit is 65,536 bytes. `AssignmentService` checks active administrator and clinician roles and audits grant/revoke in the same database transaction; it returns no clinical text. Protected HTTP and PostgreSQL tests cover assignment access/rollback, draft-without-plan, sign/edit races, immutable history and denied access. CON-03 owns the editor and history screen. OpenAPI stays unchanged until endpoint review is recorded. These checks are implementation evidence, not AT03 acceptance.
