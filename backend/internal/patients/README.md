# Patients module

Proposed owner: B. Reviewer: C. SRS: PAT-01-02; CON-01-03.

Patient registration/search with optional identity, clinician consultation drafts, immutable signing and dated addenda.

Status: TASK-PAT-01 schema and provisional validation were merged through PR #19. Migration `000005_patients.up.sql` adds patient demographics and optional supplied identity with database-generated canonical value and a unique type/canonical constraint. Migration `000010_patient_demographics.up.sql` adds DOB, gender, address and a unique registry number for `AYUR-PT-XXXXX` display codes; `000011_patient_postal_code.up.sql` adds a structured postal code for the phone-absent fallback. New registrations require DOB, gender and either a `+947XXXXXXXX` phone or a postal code. Existing rows may remain incomplete until a reviewed backfill. The latest user-supplied DEC02 text is recorded in `docs/decisions.md`; signed clinic evidence is still needed for acceptance.

TASK-PAT-02 work adds parameterized registration, ID/name/identity/contact search, demographic updates with version checks, and database-arbitrated duplicate supplied-identity conflicts. Local Sri Lankan mobile forms normalize to `+947XXXXXXXX` before storage. `ConfirmNoID` is a separate protected POST requiring normalized full legal name, exact DOB and either primary phone or, when the record has no phone or supplied ID, residential postal code. It returns one permitted exact match or a safe no-match/ambiguous result and never merges records. Patient creation and correction write audit events in the mutation transaction; a failed audit rolls back the change. Search returns at most 25 records after each candidate passes the supplied record-access policy. A missing policy denies every operation. PostgreSQL tests exercise optional identities, duplicate race, Unicode and code lookup, exact no-ID matching, postal fallback, access filtering, stale updates and forced audit failure.

A's AUTH-03 integrates the existing service with reception-only demographics authorization and protected create/search/read/update handlers in the shared HTTP transport. Every operation checks account/role/record scope in its transaction; writes require same-origin session CSRF. Routes are wired only with explicit auth configuration. See [the implementation contract](../../../docs/api/auth-03-contract.md). No patient schema or business rules were changed for this handoff. A/C/F review, DEC02/07, PAT-03 screens and AT02 acceptance remain pending. The public OpenAPI publishes only reviewed endpoints; the contract packet describes these implemented development routes for review.
